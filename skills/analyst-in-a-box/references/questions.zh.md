# 把问题对应成一次运行

[English](questions.md)

## 1. 时间说法

| 用户说 | 时间窗 |
|---|---|
| 上周 | 数据里最近一个完整周的周一到周日 |
| 上个月、上季度 | 自然月或自然季度 |
| 最近、这几天 | 有歧义：做成选择题问（近 7 天 / 近 4 周 / 本月至今） |
| 一段具体日期 | 按给的用 |

## 2. 跟谁比

| 用户说 | `--base` |
|---|---|
| 同比，或者没特别说 | `yoy`：往前 364 天的同样几个星期几，星期结构对得上 |
| 比上周、环比 | `pop`：紧挨着的前一段，同样长度 |
| 指定了基期日期 | `--base 开始 结束` |

两段的天数必须一样，否则运行会被拦下：8 天对 7 天，凭空就多出约 14%。
两段里节假日落的位置不一样时，日历检查会提示；报告里出现这条提示时要跟用户讲。

## 3. 第几阶

| 问题里的信号 | 阶 | 怎么跑 |
|---|---|---|
| 一个指标变了：「X 为什么跌了 / 涨了」 | 一阶 | 默认 |
| 变化本身变了：「增速放缓」「比上个月差」「转负」「持续下滑」 | 二阶，比两个时间段 | `--previous` |
| 两侧不一样：「A 为什么比 B 涨得快」、新客对老客、线上对线下 | 二阶，比维度两侧 | `--compare <id>` |
| 同一个公式里两项背离：「访客涨了，转化率跌了」 | 一阶 | 默认；看报告里按公式拆那一段 |

一个问题有两问（「为什么跌了，又为什么比上个月还差」），两次都跑，先给一阶的答案。

## 4. 缺东西的时候

- **工作目录里没有这个指标**：把已有的指标列成选项问用户；不要拿相近的凑。
- **用户换了个叫法**（把 `marketplace` 叫「平台」）：先问一句确认，再记一条 `add_alias` 纠正，下次直接认得。
- **`model.yaml` 里没有这组对比**：和用户确认维度和两侧，加到 `comparisons` 下，跑一次 `check`，再运行。
- **数据不够往前一年做 `yoy`**：直接说，改用 `pop`。

## 5. 缩小范围

`--filter 维度=值`（可写多次）把整次运行限定在这一块。`--dimensions a,b` 只改这一次的切分顺序；
想长期改，记一条 `set_priority` 纠正。
