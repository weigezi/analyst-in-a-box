# 采集：从几张表和文档到一个工作目录

[English](intake.md)

`init <文件夹或几个文件> --workspace W` 读每一张表，提出每张表是什么、它们怎么对上，把问题写进 `draft.json`。
`confirm` 只把答了的题变成工作目录。代码在 `scripts/aib/intake.py`。

## 1. 推断了什么，凭什么

只看数据的形状，从不看列叫什么：

| 推断 | 凭的形状 | 变成 |
|---|---|---|
| 主表 | 有日期、有数字、行数最多 | 度量（用户说清每个数是什么之后） |
| 查找表 | 没有日期；有一列一个值一行（文字或整数） | 按这个编号并进主表的属性；可以当维度，「属于」关系和单表时一样找 |
| 连接 | 一列的值都能在另一列的值里找到 | 带着对上的行数和覆盖率去问 |
| 事件记录 | 每行两个日期，前一个从不晚于后一个，再加文字或分组 | 每行一条世界事件：来源「系统记录」，状态「待确认」 |
| 节假日日历 | 同样的形状，但没有哪一列对得上数据里的分组 | 外部日历（`name`、`start`、`end`） |
| 每日序列 | 每个日期一行，或每个日期加一个分组一行 | 外部数据（天气、行业大盘）或另一份业务数据（访问量）；按分组的整数、又连得上主表的，建议当业务数据，测量值建议当外部数据 |

覆盖率 = 左边这一列的行里，值能在右边找到的比例。低于 50% 的不问；50% 到 95% 之间问，建议答「否」；95% 及以上建议答「是」。
没有明确答「是」的一律不连：没答的连接不算连接。

## 2. 问题

每一个推断都是一道题，带着建议答案和依据（行数、覆盖率、哪一列从不晚于哪一列）。做成选择题，一次问几道；建议答案就当建议给用户看。

| 题目 id | 问什么 |
|---|---|
| `main_table` | 要分析的是哪张表 |
| `kind:<表>` | 查找表 / 业务数据 / 事件 / 日历 / 序列 / 大盘 / 不用 |
| `link:<表>.<列>><表>.<列>` | 是不是同一个东西（带覆盖率） |
| `event_text:<表>`、`event_kind:<表>` | 哪一列说的是发生了什么；自己做的还是外面发生的 |
| `role:<表>.<列>` | 第二张表里的数是什么（选 `visits` 就会有 转化率 = 订单数 ÷ 访问量） |
| `market_compares:<表>` | 行业大盘拿来和主表的哪个数比 |
| 单表时的那些题 | 日期列、每个数是什么、订单编号、维度、属于关系、不营业日、单点门槛 |

关于并进来的属性（标价、商品名）的题，是按建议的连接先假设出来的。用户对某个连接答「否」，这些题就没有意义了，`confirm` 会忽略。

## 3. 文档

脚本不读文字：从句子里按规则抽原因，就是在猜。由你（AI 工具）读文档、提候选：

```yaml
doc: docs/weekly_report.md
items:
  - type: event                       # 或 mechanism
    quote: "<那一句原文，原样照抄>"
    entry: {kind: internal, start: 2026-10-12, entities: ["channel:marketplace"],
            what: {zh: "...", en: "..."}}
```

`propose --workspace W --file proposals.yaml`（只有一条时用 `--doc D --type event --quote Q --json E`）。以下情况会拒收：

- 原文在文档里找不到。空白、换行和 Markdown 的强调符号不算，其余每个字都要对上；
- 原文不到 8 个字，证明不了这句话出自哪里；
- 有不认识的实体，事件没有开始日期，或机制没有写结论。

收下的存成 `source: {kind: document, ref, quote}`、`status: proposed`，并记进 `proposals.jsonl`。
一条待确认的记录如果和变化对得上，那一块就是推测：「可能的原因，来自文档，待确认」，并附上原句。
用户确认（`correct` 的 `confirm`）之前，它不算已解释。

## 4. 每样东西是哪来的

`formation --workspace W` 把工作目录里的每一样东西分四类列出来：从数据推出的（并经选择题确认）、用户的回答、从文档抽出的（待确认）、只有人能补的。
最后一类包括：文档以外的机制、动作和负责人、确认过的切分顺序、对比组、量-结构-价格拆解、代码对应的可读名字。
`demo/intake/` 在演示店的表上跑一遍完整的采集，并把结果和手写的工作目录对照。
