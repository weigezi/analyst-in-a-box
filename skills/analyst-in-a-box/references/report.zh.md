# 呈现报告

[English](report.md)

## 1. 顺序

报告已经按读者需要的顺序排好，保持这个顺序：

1. **结论**：变了多少、主要来自哪、一件用户可能不知道的事。
2. **算不算异常**：和自己的历史比、和大盘比、节假日对不对得上。
3. **拆解**：先按公式拆，再一刀一刀切，每一刀写明为什么停或为什么往下钻。
4. **为什么**：每个单点有什么能解释它，带出处和状态。
5. **谁该做什么**：这些单点登记过的负责人和动作。
6. **待你确认**：缺口和待确认的条目。把它们变成问题去问。

对话里先用两三句话讲结论，其余的问用户要不要看。

## 2. 容易讲错的地方

- **占比超过 100%。** 一组跌得比总数还多，因为别的组在涨。就照这个讲：
  「单是电商平台就比总变化跌得还多；其他渠道涨了 X，抵掉了一部分」。不要说这是算错了。
- **结构主导 / 指标主导**（比率）。结构主导：各组占比变了（便宜的单子多了）；
  指标主导：各组自己的水平变了（每一组都变便宜了）。说清是哪一种，以及是在哪个维度下算的。
- **结构差异 / 表现差异**（比两侧）。结构差异：两侧卖的东西组合不一样。表现差异：同一样东西在两侧长得不一样。
- **分散，没有单点。** 变化分布在各组，分析是有意停下的。不要为了显得果断去挑一个「最大的」。
- **推测。** 过了三道检查的外部事件是「时间、影响的那一块、量级都对得上的推测」，不是「原因」。
  没过的是「时间上吻合，未证实」。把推翻条件也讲出来。
- **在通常范围内。** 直接说；拆解仍然有用，但这不是异常。

## 3. 数字

报告里的数字原样用。不要换一种舍入、换单位，也不要自己加百分比。用户要的数报告里没有，就换个配置再跑一次。

## 4. 缺口

缺口是报告里最值钱的一行：skill 就是从这里学的。用大白话问，一次问一个，把回答用 `correct` 记下来。
