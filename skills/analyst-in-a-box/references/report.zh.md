# 呈现报告

[English](report.md)

## 1. 顺序

报告已经按读者需要的顺序排好，保持这个顺序：

1. **结论**：变了多少、主要来自哪、一件用户可能不知道的事。
2. **算不算异常**：和自己的历史比、和大盘比、节假日对不对得上。
3. **拆解**：先按公式拆，再一刀一刀切，每一刀写明为什么停或为什么往下钻。
4. **为什么**：每个单点有什么能解释它，带出处和状态。
5. **谁该做什么**：这些单点登记过的负责人和动作。
6. **待你确认**：缺口和待确认的条目。把它们变成问题去问。

对话里先用两三句话讲结论，其余的问用户要不要看。

## 2. 容易讲错的地方

- **占比。** 报告里不会出现超过 100% 或正负方向和变化相反的占比。表格里给的是每组占全部变动幅度的比例（0～100%），正负看金额那一列。
  结论用金额讲：主因这一组变了多少、它自己涨跌多少，以及「去掉这一块，其余部分变了 X，平时是 Y」。不要自己算占比。
- **估计。** 「跟着大盘走」用的是这家店相对大盘的常态差距；报告会写明这是估计，并给出只按大盘算的那个数。两个都转述，并说清哪个是哪个。
- **从哪天开始。** 报告点出了开始日期，就拿它和列出的事件比。和事件同一天开始是很有力的证据；比事件还早开始，则不利于这个解释。
- **结构主导 / 指标主导**（比率）。结构主导：各组占比变了（便宜的单子多了）；
  指标主导：各组自己的水平变了（每一组都变便宜了）。说清是哪一种，以及是在哪个维度下算的。
- **结构差异 / 表现差异**（比两侧）。结构差异：两侧卖的东西组合不一样。表现差异：同一样东西在两侧长得不一样。
- **分散，没有单点。** 变化分布在各组，分析是有意停下的。不要为了显得果断去挑一个「最大的」。
- **推测。** 过了三道检查的外部事件是「时间、影响的那一块、量级都对得上的推测」，不是「原因」。
  没过的是「时间上吻合，未证实」。把推翻条件也讲出来。
- **在通常范围内。** 直接说；拆解仍然有用，但这不是异常。

## 3. 数字

报告里的数字原样用。不要换一种舍入、换单位，也不要自己加百分比。用户要的数报告里没有，就换个配置再跑一次。

## 4. 缺口

缺口是报告里最值钱的一行：skill 就是从这里学的。用大白话问，一次问一个，把回答用 `correct` 记下来。

## 5. 画图用的数据

`record.json` 里存着画图用到的全部数据，网页可以照着重画：

| 字段 | 里面是什么 |
|---|---|
| `charts.waterfall` | `base`、`steps`（`label_key`、`dimension`、`value`；最后一条可能是 `others`）、`current`、`unit`、`dimension`、`filters`、`base_window`、`current_window`；基期 + 各步 = 本期 |
| `charts.daily` | `current` 和 `base`，各是按位置对齐的 `[{day, value}]`，加上 `unit`、`excluded_days` |
| `charts.range` | `current_change`、`usual_range`（过去各期变化的中间一半）、`unusual_below` / `unusual_above`（判为异常的门槛线，不是正常范围）、`history`（每个过去期的 `window`、`base`、`change`） |
| `narrative` | `main`、`secondary`、`offsets`、`ruled_out`、`rest`（范围内其余部分和它平时的变化比）、`onset`（开始日期、逐日差 `daily`、对上的 `events`）、`recent_weeks`、`market`（估计） |
| `quality` | `status`、`suspect`、`failed`（停发那一档）、`warned`、`checks`（每项带 `status` 和 `level`） |
| `tree`、`pvm`、`growth_accounting` | 其他拆法，跑了才有 |

配色：下降用朱红 `#D55E00`，上升用蓝 `#0072B2`，总数用灰（Okabe & Ito 2008）；图里每个数都带正负号，负号是真正的减号。
