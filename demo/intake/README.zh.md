# 采集演示：店里的原始表变成一个工作目录

[English](README.md)

演示店手写的工作目录（`../store/workspace/`）展示的是：有人把店描述清楚之后，skill 能做什么。
这个文件夹展示的是：只给店里系统导出的表，再加一份周报，这份描述 skill 能自己形成多少。

## 里面有什么

| 路径 | 是什么 |
|---|---|
| `build_tables.py` | 把演示店的数据拆成 9 张系统导出样子的表，放在 `tables/`（订单表里只有商品编号和城市；品类和大区在查找表里） |
| `tables/` | 订单、商品、城市、流量、活动日历、调价记录、节假日日历、天气、行业大盘 |
| `docs/weekly_report.zh.md` | 一份虚构的周报，按店里平时写周报的样子写（`weekly_report.md` 是译文） |
| `answers.yaml` | 店主怎么回答采集的选择题 |
| `proposals.yaml` | AI 工具读完周报后提出的候选，每条带着原句 |
| `run_intake.py` | 跑完整的采集，写出 `workspace/`、`runs/`、`formation.json` 和形成报告 |
| `formation.zh.md` | 形成报告：形成了什么、各自从哪来、和手写工作目录哪里不一样 |

```bash
uv run python demo/intake/run_intake.py
```

`demo/store/` 只读不写。

## 它说明了什么

- skill 自己认出主表、两张查找表和 7 处表之间的连接（覆盖率都是 100%），还认出两张事件表、一份节假日日历和三份每日序列，每一样都出成选择题；
  店主改了两处建议，都在行业大盘那张：它是大盘、不只是一份序列，拿来和营收比。
- 活动日历和调价记录变成 3 条事件，标「来自系统记录，待确认」；周报里读出 2 条事件、1 条机制，每条都带着原句，标「来自文档，待确认」。
- 形成的工作目录能答营收那道题：主因是电商平台；可能的原因是平台改费用条款，显示「来自文档，待确认」，不算已解释。
  华东那道题算已解释，因为暴雨对着天气数据过了三道检查（外部事件看这道检验，不看谁确认过）。
- 形成不了的也照实列出来：代码对应的可读名字、平台抽佣金这类机制、动作和负责人、App 对比网页这组对比、确认过的切分顺序、量-结构-价格拆解。
